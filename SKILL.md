# Навык: «Инфа о ПК» (PC Report)

## ⚡ Быстрое применение (шпаргалка агента)

**1. Проверь актуальность кода:**
```bash
cd /workspace/pc-report 2>/dev/null || git clone https://github.com/XuTP00/pc_reports.git pc-report
git -C pc-report pull --ff-only
```

**2. Выбери режим и выполни:**

| Ситуация | Команда |
|---|---|
| Текущий ПК = Linux | `./pc_report.sh` |
| Текущий ПК = Windows | `powershell -ExecutionPolicy Bypass -File .\pc_report.ps1` |
| Удалённый Linux по SSH, есть ключ | `./pc_report.sh user@host [-p порт]` |
| Удалённый Linux по SSH, пароль от пользователя в чате | `PC_PASS='<пароль>' ./pc_report.sh user@host` |

**3. Результат:** файл `PC_Report_<хост>_<дата>.html` — отдай его пользователю.

---

## 📋 Полное описание

Автономный мини-сервис из **двух файлов**: `pc_report.sh` (Linux) и `pc_report.ps1` (Windows).
Каждый сам собирает полные сведения о машине и создаёт красивый структурированный HTML-отчёт
(тёмная тема VS Code, моноширинный шрифт, карточная раскладка, без внешних ресурсов).

### Состав отчёта (9 секций)
1. ОС — полное наименование, версия, разрядность, архитектура
2. Процессор — полное наименование, ядра/потоки, частота, кэш
3. Материнская плата — производитель + модель, BIOS
4. RAM — каждый модуль отдельно, количество модулей, общий объём ГБ
5. Видеокарта — наименование, видеопамять, спецификация, драйвер
6. Диски — Windows: все логические тома (имя, объём, занято); Linux: корневое блочное устройство + тома
7. Сеть — интерфейсы, IP/MAC/шлюз/DNS, режим DHCP или STATIC
8. Пользователи — имя ПК, текущий пользователь, все учётные записи
9. Сводка — терминальный вид

### Триггеры применения навыка
- «выполни навык "Инфа о ПК" на текущем ПК» → локальный запуск
- «вот доступы: ssh mike@192.168.1.154 password: ...» → SSH-режим
- «сделай отчёт о железе на <хост>» → определить ОС → выбрать скрипт

### Алгоритм для удалённого хоста (SSH)
1. Сначала проверить стандартные ключи: `~/.ssh/id_rsa`, `id_ed25519` (скрипт делает это сам через BatchMode).
2. Если ключей нет/не подошли — запросить пароль у пользователя в сессии.
3. Передать пароль ТОЛЬКО через переменную окружения: `PC_PASS='...' ./pc_report.sh user@host`.
4. После работы убедиться, что нигде не осталось временных файлов (скрипт чистит их по trap).

### 🔒 Железные правила безопасности
- Пароли НЕ сохраняются: ни в файлы, ни в git, ни в историю, ни в HTML-отчёт.
- Запрашивать пароль только если ключи не сработали.
- На удалённой Windows-машине: скопировать `pc_report.ps1` → запустить → забрать HTML → удалить копию.

### ⚠️ Известные грабли
| Симптом | Причина | Лечение |
|---|---|---|
| `syntax error near '[string]$Output'` | скачан PowerShell-файл вместо bash / битый файл | перескачать с GitHub, первая строка должна быть `#!/usr/bin/env bash` |
| Ошибки кодировки в PS 5.1 («РџС±Рѕ...») | файл сохранён без UTF-8 BOM | брать актуальный `pc_report.ps1` из репо (BOM включён), не пересохранять в редакторах без BOM |
| Пустые поля RAM/платы | нет root-доступа к SMBIOS | `sudo ./pc_report.sh` или игнорировать (в VM так и должно быть) |
| CRLF-проблемы после скачивания с Windows | `\r` в конце строк | `sed -i 's/\r$//' pc_report.sh && chmod +x pc_report.sh` |

### Ограничения
- macOS не поддерживается; удалённый сбор по SSH — только для Linux-хостов.
- В Docker/VM часть DMI-данных недоступна без привилегий.
