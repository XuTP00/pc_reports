# Инфа о ПК

## Назначение
Навык запускает мини-сервис **PC Report** и создаёт красивый структурированный HTML-отчёт
с полными сведениями о ПК: ОС (наименование, версия, разрядность, архитектура), процессор,
материнская плата, модули ОЗУ, видеокарты (объём VRAM и спецификации), диски (тома Windows /
root-устройство Linux), сетевые интерфейсы с режимом DHCP/STATIC, имя компьютера и все пользователи.

Дизайн отчёта (зафиксирован, не менять без указаний пользователя):
тёмная тема VS Code + корпоративный синий, моноширинный шрифт, **вариант A — карточная раскладка**,
заголовок `PC▪REPORT` + Имя компьютера + Дата, без упоминаний об ИИ, полностью автономный HTML.

## Расположение файлов
Сервис лежит в `/workspace/pc-report/`:
- `pc_report.sh` + `collect.sh` — запуск на текущем Linux-ПК
- `pc_report.ps1` — запуск на текущем Windows-ПК (PowerShell 5.1+)
- `pc_report_remote.sh` — запуск на удалённом Linux-ПК по SSH

## Триггеры (как пользователь может попросить)
1. **«Выполни навык "Инфа о ПК" на текущем ПК»** → локальный запуск.
2. **«Вот доступы на ПК: ssh mike@192.168.1.154 password: 1234567»** → удалённый запуск.
3. Любой похожий запрос («сделай отчёт о железе», «HTML-отчёт о конфигурации ПК»).

## Процедура выполнения

### Шаг 0. Определить целевую машину
- Локально или удалённо (есть ли доступы user@host).
- Для удалённого — определить ОС цели (Linux → pc_report_remote.sh; Windows → см. п. «Удалённый Windows» ниже).

### Шаг 1а. Текущий ПК (Linux)
```bash
cd /workspace/pc-report && ./pc_report.sh -o PC_Report_$(hostname)_$(date +%Y%m%d_%H%M%S).html
```

### Шаг 1б. Текущий ПК (Windows)
```powershell
powershell -ExecutionPolicy Bypass -File .\pc_report.ps1 -Output .\PC_Report_<host>_<timestamp>.html
```

### Шаг 2. Удалённый ПК по SSH (Linux-цель)
Порядок аутентификации (строго соблюдать):
1. **Сначала проверить SSH-ключи в стандартных местах**: `~/.ssh/id_rsa`, `~/.ssh/id_ed25519`, `~/.ssh/id_ecdsa`. Скрипт сам их перебирает (`BatchMode`).
2. Если ключей нет/не подошли — **спросить у пользователя данные в текущей сессии** (например: «SSH-ключи не подходят. Предоставьте пароль для mike@192.168.1.154?»).
3. Если пользователь отказался — сообщить, что отчёт не создан, и завершить.
4. Если пользователь дал пароль в сообщении (или отвечает в чате) — использовать его так:
   ```bash
   cd /workspace/pc-report && PC_PASS='<пароль из сообщения>' ./pc_report_remote.sh mike@192.168.1.154 -o PC_Report_<host>_<timestamp>.html
   ```

**ЖЁЛКИЕ ПРАВИЛА БЕЗОПАСНОСТИ (нарушение недопустимо):**
- Пароль существует **только внутри одной команды/сессии**. Запрещено:
  ❌ писать пароль в любой файл (в т.ч. временный, .netrc, expect-скрипт, history-файл);
  ❌ сохранять в переменные между шагами/командами дольше одного запуска;
  ❌ выводить пароль в логи, в HTML-отчёт, в ответы после завершения;
  ❌ использовать `sshpass -p` (пароль виден в `ps`) — только `PC_PASS` + `sshpass -e`.
- После работы скрипт сам удаляет свои временные файлы на удалённой машине (trap EXIT).
- В отчёте паролей быть не может — сервис собирает только системную информацию.

### Шаг 3. Удалённый Windows-ПК
Если цель — Windows по WinRM/PSExec недоступен, предложить пользователю два варианта:
1. Пользователь копирует `pc_report.ps1` на целевой ПК и запускает локально, присылает HTML.
2. Если открыт SSH на Windows (OpenSSH Server) — тот же подход: ключи → при отсутствии спросить пароль → выполнить `pc_report.ps1` через `ssh` и скачать результат `scp`.

### Шаг 4. Проверка результата
- Файл существует, размер > 8 КБ, содержит секции `id="os|cpu|mb|ram|gpu|disk|net|users|summary"`.
- Быстрая проверка: `grep -c 'class="card"' <файл>` ≥ 10 и отсутствие слова «ВАРИАНТ» (это были только тестовые баннеры).
- Сообщить пользователю полный путь к файлу и кратко — ключевые параметры из отчёта (ОС, CPU, RAM, GPU, диск root/том C:).

## Структура отчёта (вариант A, зафиксирована)
Hero-заголовок `PC▪REPORT` + КОМПЬЮТЕР / ДАТА ОТЧЁТА / ПОЛЬЗОВАТЕЛЬ + бейджи → липкая навигация →
секции 01–09 карточками в сетке 2-в-ряд: ОС · Процессор · Материнская плата · Память (таблица модулей) ·
Видеокарта (VRAM+спецификации) · Диски (полосы заполнения) · Сеть (пилюли DHCP/STATIC) ·
Пользователи (все аккаунты) · Сводка (терминальный вид). Footer: скрипт, дата, хост.

## Обработка ошибок
- Нет прав на SMBIOS-данные (RAM-модули/плата) → сервис пишет «данные недоступны», это нормально, предупреждать пользователя, что часть полей пустует без root.
- SSH-подключение не удалось → сообщить причину (timeout/auth), переспросить доступы один раз.
- На удалённой машине нет bash — сервис не применим, объяснить.
