# Навык: «Инфа о ПК»

## 📌 Что это
Мини-сервис «PC Report»: собирает полные сведения о компьютере и создаёт
**один автономный HTML-отчёт** (тёмная тема VS Code, моноширинный шрифт,
карточная раскладка варианта A, без внешних ресурсов и JavaScript).

Сервис состоит ровно из **двух исполняемых файлов**:

| Файл | ОС | Роль |
|---|---|---|
| `pc_report.sh`  | Linux   | единый скрипт: встроенный сборщик данных + генератор HTML. Умеет собирать данные локально И по SSH с удалённого Linux-ПК |
| `pc_report.ps1` | Windows | PowerShell-скрипт: сбор через WMI/CIM + генерация HTML. Работает только локально на том ПК, где запущен |

Оба файла лежат в `/workspace/pc-report/`. Никаких других зависимостей нет.

---

## 🎯 Когда применять навык
Пользователь просит информацию о ПК в одной из двух формулировок:

1. **«Выполни навык "Инфа о ПК" на текущем ПК»** → локальный режим.
2. **«Вот доступы на ПК: ssh mike@192.168.1.154 password: 1234567 — примени навык»** → удалённый режим.

## 🔁 Алгоритм агента (строго по шагам)

### Шаг 1. Определить цель выполнения
- Указан хост/доступ (ssh user@ip) → **удалённый режим**, переход к шагу 3.
- Хост не указан → **локальный режим** на текущем ПК, переход к шагу 2.

### Шаг 2. Определить ОС целевого ПК
```bash
uname -s        # Linux → pc_report.sh
                # MINGW*/CYGWIN* → тоже pc_report.sh (ограниченно), лучше PowerShell
```
На текущем ПК из-под Windows агент определяет ОС через
`$env:OS` / `Get-CimInstance Win32_OperatingSystem` и выбирает `pc_report.ps1`.
macOS не поддерживается — сообщить пользователю и остановиться.

### Шаг 3. Удалённый режим

#### 3а. Если целевой ПК — Linux:
```bash
cd /workspace/pc-report

# приоритет 1: SSH-ключи в стандартных местах (~/.ssh/id_rsa, id_ed25519 и т.п.)
./pc_report.sh user@host                      # ключ подошёл — пароль не нужен

# приоритет 2: ключей нет/не подошли — взять пароль у пользователя В СЕССИИ
# (спросить открытым вопросом), затем передать ТОЛЬКО через переменную окружения:
PC_PASS='<пароль_из_сессии>' ./pc_report.sh user@host [-p порт] [-o имя.html]
```
Скрипт сам: проверит соединение, определит удалённую ОС, передаст встроенный
сборщик по stdin, выполнит его на хосте, соберёт вывод и **создаст HTML-отчёт
локально** (имя `PC_Report_<хост>_<дата>.html`).

#### 3б. Если целевой ПК — Windows:
Удалённого режима «на лету» у ps1-скрипта нет. Порядок действий агента:
1. Скопировать `pc_report.ps1` на целевой ПК доступным способом
   (SCP/SFTP, SMB-шара, `winrs`, WinRM `Invoke-Command`).
2. Запустить его **там локально**:
   `powershell -ExecutionPolicy Bypass -File C:\...\pc_report.ps1 -Output C:\...\report.html`
3. Забрать готовый `report.html` обратно на свой ПК (тем же каналом).
4. Удалить копию скрипта и временные файлы с целевого ПК.
Если ни один канал недоступен — сказать пользователю и предложить запустить
`pc_report.ps1` вручную на том ПК и прислать файл.

### Шаг 4. Проверка результата
- Отчёт создан, размер > 10 КБ, в `<title>` есть имя хоста.
- Кратко пересказать пользователю ключевые строки сводки (ОС/CPU/RAM/GPU/диски/сеть)
  и путь к файлу.

## 🔐 Правила работы с учётными данными (обязательны)
1. **Сначала искать SSH-ключи** в стандартных местах: `~/.ssh/id_*`,
   `/etc/ssh/*_key`, конфиг `~/.ssh/config`. Если вход по ключу проходит —
   пароль вообще не запрашивать.
2. Ключей нет или они не подошли — **спросить логин/порт/пароль у пользователя
   в текущей сессии**. Если пользователь не предоставил данные — отказать в
   выполнении и объяснить причину.
3. Пароль передаётся **только через переменную окружения `PC_PASS`** (или
   интерактивный hidden-запрос внутри скрипта).
4. **Запрещено**: записывать пароли/хосты/логины в любые файлы, в историю
   команд, в логи, в HTML-отчёт, в git; использовать `sshpass`; сохранять
   known_hosts записи удалённых хостов (скрипт пишет в /dev/null).
5. Сеанс окончен — следов доступа не осталось: временный askpass-файл и
   временный сборщик удаляются скриптом автоматически (trap на EXIT/INT/TERM).
6. Данные, полученные в процессе (характеристики ПК), сохраняются только в
   итоговом HTML-отчёте — это и есть результат работы.

## 📊 Состав отчёта (9 секций, вариант A — карточный)
1. **ОС** — полное наименование, версия, ядро, архитектура, разрядность, тип окружения (bare metal/VM/контейнер/облако), аптайм.
2. **Процессор** — полное наименование, производитель, сокеты, ядра/потоки, частота, кэш L3, флаги инструкций.
3. **Материнская плата** — полное наименование (вендор+модель), версия, BIOS/UEFI (версия, дата).
4. **Память** — общий объём ГБ, число модулей, таблица по каждому модулю (производитель, Part Number, объём, тип DDR, частота).
5. **Видеокарта** — полное наименование, шина PCI, драйвер, объём видеопамяти и спецификации.
6. **Диски** — *Windows*: все логические тома (имя, ФС, общий объём, занято, свободно + цветовой индикатор); *Linux*: блочное устройство корня (имя, ФС, объём, занято) и список физических дисков.
7. **Сеть** — каждый интерфейс: MAC, IPv4, шлюз, DNS, режим **DHCP/STATIC** (цветная пилюля).
8. **Пользователи** — имя ПК, кто запустил скрипт, все пользователи системы, активные сессии.
9. **Сводка** — терминальный вид (hostname/os/cpu/ram/gpu/disks/network/user).

Шапка: крупный заголовок `PC▪REPORT` + имя компьютера + дата отчёта + бейджи
ключевых параметров. Липкая навигация по секциям. В удалённом режиме в шапке
дополнительно помечается «удалённый сбор по SSH». В файле нет никаких
упоминаний об ИИ.

## 🖥 Команды запуска (справка)
```text
Linux, локально:    ./pc_report.sh                     # отчёт в текущей папке
                    ./pc_report.sh -o my_report.html   # в заданный файл
Linux, удалённо:    ./pc_report.sh user@host           # по SSH-ключу
                    PC_PASS='xxx' ./pc_report.sh user@host -p 22 -o r.html
Windows, локально:  powershell -ExecutionPolicy Bypass -File .\pc_report.ps1
                    .\pc_report.ps1 -Output D:\report.html
```

## ⚠️ Типичные проблемы
| Симптом | Причина / решение |
|---|---|
| `Permission denied` при запуске | `chmod +x pc_report.sh` |
| Пустые поля платы/BIOS/модулей RAM | Нет доступа к DMI (контейнер/VM) — запускать с sudo или на хосте; в VM часть SMBIOS заполнена заглушками |
| Нет модели GPU | headless-среда без lspci — ставится `pciutils`; для NVIDIA нужен `nvidia-smi` |
| Ошибка DHCP-режима интерфейса | Нет nmcli/networkctl — показывается «статическая/manual» как значение по умолчанию |
| `не удалось войти на host` | Неверный логин/порт/пароль; проверить доступность: `nc -zv host 22` |
| Windows-машина по SSH | OpenSSH-сервер на Windows принимает команды, но ps1-скрипт требует копирования и запуска на самой машине (шаг 3б) |
| PS policy blocked | `Set-ExecutionPolicy -Scope Process Bypass` |

## ⛔ Ограничения сервиса
- macOS не поддерживается.
- Удалённый сбор «на лету» реализован только для Linux-хостов; для Windows —
  схема «скопировать → запустить там → забрать HTML → удалить копию».
- Отчёт статичен (без JS): открывается в любом браузере и корректно печатается.
